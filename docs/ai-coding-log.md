# AI 코딩 도구 사용 기록

## 사용 도구

- OpenAI Codex
- 사용일: 2026-08-13

## 주요 요청

```text
A1-3 요구사항을 만족하는 50대 여성 대상 AI 5분 운동 추천 웹 서비스를
바닐라 HTML/CSS/JavaScript와 Vercel Python Function으로 구현한다.
3개 이상 섹션, 반응형, 입력·결과 UX, 빈 입력·API 오류·타임아웃 처리를 포함한다.
```

## 생성 후 검토·수정 기준

- 프론트와 `api/` 백엔드 구조 분리
- API 키를 `GEMINI_API_KEY` 환경 변수로만 읽음
- 허용 입력값 검증과 길이 제한 적용
- AI 출력은 JSON Schema로 제한하고 화면 출력 시 HTML 이스케이프 적용
- 의료 진단 표현을 금지하고 운동 중단 기준을 표시
- 모바일 메뉴, 키보드 포커스, 상태 알림을 포함

## 오류 대응 기록

개발 과정에서 예상되는 실패를 사전에 테스트 항목으로 정의했습니다.

1. 필수값 누락: 프론트에서 요청 전 차단
2. API 키 누락: 서버에서 503과 사용자용 메시지 반환
3. 외부 API 무료 한도 오류: 502로 변환해 키나 내부 정보를 노출하지 않음
4. 응답 지연: 브라우저 20초, 서버 15초 타임아웃 적용

## 배포 오류와 수정 기록

1. 첫 배포에서 Vercel이 프로젝트 전체를 Python 애플리케이션으로 잘못 감지해
   `No python entrypoint found` 오류가 발생했습니다.
2. 원인은 정적 프론트엔드와 `api/`의 Python 함수가 함께 있는 구조를 Python
   프레임워크 프로젝트로 자동 감지한 것이었습니다.
3. Vercel Framework Preset을 `Other`로 변경해 정적 파일은 그대로 제공하고
   `api/routine.py`만 Serverless Function으로 처리하도록 수정했습니다.
4. 재배포 후 Production 상태가 `Ready`이고 메인 화면과 4개 섹션이 공개 URL에서
   표시되는 것을 확인했습니다.

이 과정으로 오류 메시지의 핵심 원인을 확인하고, 코드 구조를 바꾸기보다 배포 환경의
잘못된 자동 감지 설정을 수정하는 대응 흐름을 기록했습니다.

## 결제 없는 AI API 전환

OpenAI API 키는 정상 등록했지만 계정 크레딧이 없어 실제 요청이 한도 오류로
거절되었습니다. 과제 진행 중 결제를 피하기 위해 Gemini API 무료 등급으로 전환했습니다.
백엔드 환경 변수는 `GEMINI_API_KEY`, 모델은 안정 버전인
`gemini-2.5-flash-lite`를 사용하고 JSON Schema 기반 구조화 출력을 유지했습니다.
